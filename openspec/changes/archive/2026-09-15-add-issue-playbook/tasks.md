## 2. Claim protocol

- [x] 2.1 Implement the claim: per-candidate comment pre-check for the `<!-- ptah:issue-claim -->` marker, claim comment post (marker + fixed legible sentence, no data fields), optional `claimedLabel` add (queue label preserved), read-back of all claim markers via the REST comments endpoint, earliest-wins by `created_at` with the numeric REST comment `id` as tie-break (the GraphQL node id is not orderable), a losing attempt that writes nothing further (its losing marker stays as audit noise), backoff to next candidate (scan mode) or lost-claim error (explicit mode); verify in a sandbox repo that a pre-existing claim makes the issue ineligible, that the queue label survives the claim, and that an issue carrying only a losing marker stays ineligible until every claim marker is deleted
- [x] 2.2 Verify contention: run two scratch `pickUp()` runs concurrently against one sandbox queue; verify exactly one winner per issue, the loser claims a different issue or returns `no-eligible-issue`, and the loser never writes a second comment to the contended issue beyond its own losing claim; verify that deleting only the winner's marker leaves the issue ineligible (the losing marker persists) and that deleting every claim marker requeues the issue
- [x] 2.3 Verify claimedness is the marker, not the label: in a sandbox, confirm an issue carrying a claim marker stays ineligible after `claimedLabel` removal and becomes eligible only after the marker comment is deleted, that an issue whose claim markers were deleted but whose `claimedLabel` remains is eligible again (the label is never a gate and never narrows the scan), and that a config without `claimedLabel` behaves identically (the marker is the only signal)
